# Telegram-бот для записи по времени

Бот записи на приём для одного специалиста: клиент выбирает услугу, дату и свободное время, может отменить или перенести запись; админ управляет расписанием и услугами прямо в Telegram и выгружает записи в Excel или Google Таблицу. Бот сам присылает напоминания за 24 часа и за 2 часа до приёма.

Стек: Python 3.11+, aiogram 3, SQLAlchemy 2 (async) + SQLite, APScheduler, openpyxl, gspread.


## Сценарии

### Клиент

- `/start` — приветствие и список активных услуг. Если услуг нет, бот сообщает об этом. Команды `/start` и `/my` также видны в меню команд бота. На любое другое сообщение, когда нет активного сценария, бот отвечает короткой подсказкой с этими командами.
- Запись: услуга, затем дата (14 дней, начиная со следующего дня: запись на сегодня закрыта, граница считается по `TIMEZONE`), затем свободное время, затем подтверждение. Если выбранное время занято, уже прошло или относится к сегодняшнему дню, бот предлагает выбрать другое. Перенос записи подчиняется тому же правилу.
- `/my` — предстоящие записи. Каждую можно отменить (с подтверждением) или перенести на другую дату и время.
- Отмена и перенос доступны, пока до приёма осталось не меньше `CANCEL_DEADLINE_HOURS` часов; позже бот отвечает, что изменить запись уже нельзя.
- Напоминания приходят за 24 часа и за 2 часа до приёма. Если запись создана уже внутри этого окна, напоминание не дублируется.

### Админ

Админ-панель включена, только если задан `ADMIN_IDS`. Команда `/admin` (только для этих id и только в личном чате с ботом: в группах панель не отвечает) открывает меню:

- **График работы** — по каждому дню недели: часы вида `10:00-18:00`, с перерывом `10:00-18:00 14:00-15:00`, либо «Выходной». Если на этот день недели уже есть будущие записи вне нового графика (выходной, более короткие часы или перерыв поверх записи), бот показывает их и просит подтверждение; сами записи не отменяются, их нужно отменить вручную.
- **Закрыть день** — закрывает конкретную дату, всегда с подтверждением. Если на неё есть записи, бот показывает их; записи отменяются, клиенты получают уведомление, а если кого-то уведомить не удалось (например, клиент заблокировал бота), бот называет его имя.
- **Закрытые дни** — список всех закрытых дат, начиная с сегодняшней; нажатием день открывается снова (уже отменённые записи не восстанавливаются).
- **Услуги** — добавить услугу (название, длительность в минутах, цена), изменить любое из полей, скрыть услугу от клиентов.
- **Записи на день** — список записей выбранного дня, с возможностью отменить запись (клиент получает уведомление; если отправить его не удалось, бот сообщает об этом).
- **Экспорт записей** — период «Сегодня», «7 дней» (сегодня и 6 следующих дней) или «Месяц» (текущий календарный месяц), формат Excel или Google Таблица.

### Экспорт

Колонки: ID, Дата и время, Клиент, Телефон, Услуга, Цена, Статус (активна / отменена / выполнена). В выгрузку входят записи любого статуса.

- **Excel** — бот присылает в чат файл `bookings_<с>_<по>.xlsx` с листом «Записи».
- **Google Таблица** — бот полностью перезаписывает лист «Записи» (создаёт, если его нет) и присылает ссылку на таблицу. Если Google не настроен, бот пишет админу инструкцию.

## Быстрый старт

### 1. Токен бота

Откройте в Telegram [@BotFather](https://t.me/BotFather), отправьте `/newbot`, задайте имя и username. BotFather пришлёт токен вида `123456:ABC...`, это значение `BOT_TOKEN`.

### 2. Telegram id админа

Свой числовой id можно узнать у любого бота-«определителя id», например [@userinfobot](https://t.me/userinfobot). Несколько админов указываются через запятую: `ADMIN_IDS=111111111,222222222`.

### 3. Файл `.env`

```bash
cp .env.example .env
```

Заполните `BOT_TOKEN` и `ADMIN_IDS`, остальное можно оставить по умолчанию (см. таблицу ниже).

### Запуск локально

Нужен Python 3.11 или новее.

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m app.main
```

База создаётся автоматически в `./data/bookings.db` (папка `data/` создаётся при старте).

### Запуск в Docker

```bash
docker compose up -d --build
docker compose logs -f
```

- Контейнер читает настройки из `.env` (`env_file`), перезапускается сам (`restart: unless-stopped`) и работает не от root.
- База лежит в именованном томе `bot-data`, примонтированном в `/app/data`. Значение `DATABASE_URL` по умолчанию (`./data/bookings.db`) уже указывает туда, менять его не нужно. Данные переживают `docker compose down` и пересборку; том удаляет только `docker compose down -v`.
- Папка `./credentials` монтируется в контейнер как `/app/credentials` только для чтения. Для Google Таблицы в `.env` нужно указать **путь внутри контейнера**: `GSHEETS_CREDENTIALS_PATH=/app/credentials/service-account.json`.
- Контейнер работает под пользователем с uid 1000, поэтому JSON-ключ на хосте должен быть читаем для него (например, `chmod 644 credentials/service-account.json`).
- Бот работает через long polling, открывать порты не нужно.

После запуска напишите боту `/start`: должно прийти приветствие и (если вы уже добавили услуги через `/admin`) список услуг.

## Настройка Google Таблицы

Нужна только для экспорта в Google; без неё работает экспорт в Excel.

1. В [Google Cloud Console](https://console.cloud.google.com/) создайте проект (или выберите существующий) и включите для него **Google Sheets API** и **Google Drive API**.
2. Создайте **сервисный аккаунт** (IAM и администрирование, Сервисные аккаунты) и на вкладке «Ключи» создайте JSON-ключ.
3. Сохраните файл как `credentials/service-account.json`. Папка `credentials/` в `.gitignore`, **никогда не коммитьте ключ**.
4. Создайте Google Таблицу (или откройте существующую) и дайте доступ **редактора** на email сервисного аккаунта (поле `client_email` в JSON).
5. В `.env` укажите:
   - `GSHEETS_SPREADSHEET_ID` — часть адреса между `/d/` и `/edit`: `https://docs.google.com/spreadsheets/d/<ID>/edit`;
   - `GSHEETS_CREDENTIALS_PATH` — `credentials/service-account.json` локально или `/app/credentials/service-account.json` в Docker.
6. Перезапустите бота. Экспорт в Google включается, только когда заданы **обе** переменные.

## Переменные `.env`

| Переменная | По умолчанию | Описание |
|---|---|---|
| `BOT_TOKEN` | нет, обязательна | Токен бота от @BotFather |
| `ADMIN_IDS` | пусто | Telegram id админов через запятую. Пусто: админ-панели нет |
| `TIMEZONE` | `Europe/Moscow` | Часовой пояс (IANA), в нём считаются рабочие часы, даты и напоминания |
| `SLOT_STEP_MIN` | `30` | Шаг сетки слотов, минут |
| `CANCEL_DEADLINE_HOURS` | `2` | За сколько часов до приёма клиент ещё может отменить или перенести запись |
| `DATABASE_URL` | `sqlite+aiosqlite:///./data/bookings.db` | Адрес БД (SQLAlchemy async). Проверено только с SQLite |
| `GSHEETS_CREDENTIALS_PATH` | пусто | Путь к JSON-ключу сервисного аккаунта Google |
| `GSHEETS_SPREADSHEET_ID` | пусто | ID Google Таблицы для экспорта |

## Тесты

```bash
pip install -r requirements.txt   # pytest и pytest-asyncio входят в requirements
python -m pytest -q
```

Тесты не требуют токена, сети и Google: Telegram и Google подменяются заглушками, БД в памяти. Отдельный тест следит, чтобы `.env.example` перечислял ровно те переменные, что есть в `Settings`.

## Архитектура

- `app/services/` — бизнес-логика (записи, слоты, напоминания, экспорт) без зависимости от aiogram; её можно тестировать и использовать отдельно от бота.
- `app/bot/` — хендлеры aiogram, клавиатуры, фильтр админа; тексты на русском собраны в `app/utils/texts.py`.
- `app/db/` — модели SQLAlchemy и подключение.
- Свободные слоты **вычисляются на лету** из графика работы, длительности услуги и существующих записей; заранее слоты в БД не хранятся.
- Время в БД хранится в **UTC**, в локальное время (`TIMEZONE`) оно переводится только для показа и расчёта расписания.
- Напоминания рассылает APScheduler: задача раз в минуту проверяет ближайшие записи.

## Известные ограничения

- Один специалист и одно расписание на бота: нескольких мастеров нет.
- Миграций (Alembic) нет: таблицы создаются через `create_all` при старте. Изменение схемы потребует ручной миграции или новой БД.
- Бот рассчитан на один процесс: защита от двойной записи на одно время использует `asyncio.Lock` и не работает между несколькими процессами или контейнерами.
